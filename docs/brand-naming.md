# Brand and naming

Nischit is the product and repository name. Use this spelling consistently in code comments, documentation, interface text, and issue reports.

## Product description

Preferred descriptor: **lab supply operations platform**. Describe capabilities in terms of recorded procurement, evidence, receiving, QA, inventory, recall, and settlement workflows. Do not imply that recorded evidence proves physical quality, that every event is captured, or that the software is certified or compliant.

## Interface language

Use established domain terms from [the domain-language glossary](domain-language.md). Keep navigation labels direct: Procurement, Receiving, Inventory, QA, Settlement, Recall, and Evidence. Avoid naming individual modules as separate products.

## Naming changes

Do not introduce a new product, module, or integration brand without documenting its purpose, checking for conflicts, and updating contributor-facing references. Product naming must not imply a supported integration, certification, or production capability that has not been verified.
