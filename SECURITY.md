# Security policy

Nischit handles tenant-scoped operational records and may be configured with identity, storage, and payment integrations. Treat security reports as sensitive.

## Reporting a vulnerability

Do not open a public issue for an unpatched vulnerability or include exploit details, credentials, private keys, patient data, or customer records in a public report.

Use GitHub's private vulnerability reporting for this repository when it is enabled. If it is unavailable, contact the repository maintainer through the GitHub profile linked from the repository and request a private reporting channel.

Please include the affected version or commit, impact, reproduction steps, and any proposed mitigation. We will acknowledge reports and coordinate a fix and disclosure timeline with the reporter.

## Supported versions

Only the latest version on the default branch is currently supported. Release-specific support will be documented when versioned releases are established.

## Security boundaries

Do not use real patient or customer data in issues, pull requests, examples, or development fixtures. Public-chain transactions and addresses can expose metadata; a commitment does not make its source data private or prove physical-world accuracy.
